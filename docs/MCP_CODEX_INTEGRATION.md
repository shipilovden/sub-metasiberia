# Codex / MCP в Метасибири

Статус на 2026-10-08: реализация в рабочем дереве. Наличие исходников и успешная сборка **не подтверждают** применение релиза или видимый результат в клиенте.

## Подключение

Qt-панель «ИИ» запускает установленный Codex app-server с существующим входом Codex. Игровой клиент не хранит OpenAI API key. Локальный MCP слушает только `127.0.0.1`, обычно `http://127.0.0.1:8095/mcp`. Его запросы идут по HTTPS к `/mcp` подключённого игрового сервера с сохранённым игровым логином.

Настройки входа, запуск Codex и расположение панели принадлежат `CodexAppServerClient`, `AIDockWidget` и `MainWindow`. Механизм входа сохранён. Включение MCP и порт перенесены в «ИИ → Настройки», а из общего диалога настроек клиента удалены. Галочка применяет изменение сразу, без кнопки OK. По умолчанию значение false; явно сохранённый выбор пользователя сохраняется. При выключении/смене порта останавливается прежний Codex и endpoint, при включении стартует актуальное соединение. При смене сервера/мира Qt пересоздаёт локальный endpoint, чтобы не продолжать работать с предыдущим миром.

Активный мир передаётся в `X-Substrata-World`; `__root__` обозначает корневой мир. Запрос без контекста отклоняется, а не переключается молча в корневой мир. Ответ каждого инструмента содержит `world`. Устаревший клиент без этого заголовка необходимо обновить.

## Референсы, модель и визуальная обратная связь

Qt-панель имеет вкладку «Чат» и вкладку настроек с Lucide-шестерёнкой (tooltip и accessible name «Настройки»). Справка «Как это работает» находится в настройках. В чате обозначения модели и рассуждения заменены Lucide-иконками с подсказками и accessible names. Панель принимает до 8 изображений на сообщение: кнопка со скрепкой, Ctrl+V в поле ввода, перетаскивание в чат. Отображаются миниатюры; выбранное вложение можно убрать. Файлы проверяются (32 МБ / 64 Мп), нормализуются в PNG с длинной стороной до 2048 px и хранятся во временном каталоге до закрытия панели. `turn/start.input` содержит настоящие `localImage`, а не только имена файлов. Изображения отправляются в Codex вместе с сообщением, не публикуются ресурсами игрового мира.

Список моделей и уровней рассуждения запрашивается через `model/list` с пагинацией. Используются возвращённые `model`, `displayName`, `inputModalities`, `supportedReasoningEfforts`. Выбор применяется к следующему сообщению через `turn/start.model/effort`. Отказ optional model discovery не выключает чат; остаётся модель Codex по умолчанию. Если модель явно не поддерживает изображения, отправка вложений блокируется с объяснением. Механизм входа и чекбокс включения MCP не изменены.

Локальный `render_view` подключён через Qt adapter к существующему offscreen photo capture с отдельной камерой. Возвращает PNG 16..2048 px, без UI мира; сохраняет GL/camera state. Не перемещает аватар и не меняет streaming camera. Видит только загруженные рядом объекты, поэтому дальняя незагруженная геометрия может отсутствовать. Во время загрузки ресурсов возвращается ошибка с предложением повторить. Map/XR capture отклоняется. Работа ставится в очередь GUI, ожидание worker ограничено 10 секундами; ожидающий захват отменяется при timeout, без `BlockingQueuedConnection`/deadlock на shutdown. GPU-вызов, уже начавший исполняться, этим timeout не прерывается. Qt bridge добавляет инструмент через структурный разбор `result.tools`, независимо от форматирования JSON; прежний поиск точной строки `"tools":[` пропускал pretty-printed серверные схемы.

### Построение по чертежу

Когда пользователь прикладывает технический рисунок, инструкции Codex требуют сначала определить виды, единицы, размерные линии, выноски и базы; затем свести размеры в план построения. Миллиметры и сантиметры переводятся в метры. Виды сопоставляются в координатах проекта: спереди X/Z, сбоку Y/Z, сверху X/Y, вверх — +Z. Явные размеры имеют приоритет над измерениями по пикселям; масштаб с изображения служит лишь оценкой для неподписанных размеров. Противоречия и критичные отсутствующие размеры должны быть обозначены до точного построения.

После сборки ИИ должен сверить `get_object` bounds с планом, запросить `render_view` спереди, сбоку и сверху, если endpoint доступен, и исправить ту же модель. В чат передаются растровые изображения, а не PDF/DXF/DWG; чертёж не превращается в точную CAD-модель автоматически. Если размеры не читаются или модель изображения не поддерживает image input, ИИ должен сообщить об этом, а не выдавать догадку за точный размер.

## Меши и примитивы

`build_mesh.parts` принимает `box`, `sphere`, `cylinder`, `cone`, `torus`, `tube`, `rounded_box`, `lathe`, `extrude`, `deformed_box` и библиотечные примитивы. У каждой части есть `center`, `size`, `rotation` (XYZ в градусах) и `material` (индекс палитры). Обычные части собираются в один объект, но пересечения между ними не объединяются автоматически. Для настоящих отверстий/объединения/пересечения в том же рецепте задайте последующей части `operation: "subtract"`, `"union"` или `"intersect"`; база и операнд должны быть закрытыми согласованными manifold-мешами, максимум 4096 треугольников на каждый операнд. Это позволяет сразу строить, например, короб с отверстием, не создавая отдельный cutter-объект.

Для отверстия или выреза в уже существующей стене, полу, крыше, мебели или другом редактируемом native `.bmesh` объекте используйте `boolean_mesh` с `operation: "subtract"`, указав UID выбранного объекта и UID замкнутого cutter-меша. Инструмент сохраняет материалы цели, включая slash-разделённые внутренние URL текстур. Цель и cutter должны иметь одинаковый object transform; оба меша должны быть закрытыми, manifold и не превышать 4096 треугольников. Voxel и специализированные объекты требуют отдельного workflow.

У формы `extrude` можно задать `holes`: массив из 1..16 внутренних XY-контуров. Каждый контур вырезается насквозь по всей глубине. Контуры должны быть простыми, находиться внутри внешней границы и не касаться друг друга. Сквозные вырезы вычисляются ограниченной Boolean-операцией.

`tube` строит плавно ориентированную трубчатую оболочку вдоль локальной 3D-ломаной. Задайте `path` из 2..128 точек, `tube_radius`, `segments` и при необходимости `closed: true`. Открытая труба получает заглушки на концах; `closed` замыкает путь без торцов. Точки должны быть различимы, без дубликатов подряд и резкого разворота почти на 180°. Применения: кабели, трубы, поручни и ветви.

`validate_mesh` не меняет объект. Он сообщает количество граничных и неманифолдных рёбер, связных компонентов, вырожденных/дублированных треугольников и UV, а также согласованность winding и нормалей. `boolean_compatible` — отдельная предварительная проверка для meshes до 4096 треугольников; она также ищет самопересечения и несовместимую ориентацию оболочек. Проверка топологии не оценивает художественное качество и не заменяет визуальный просмотр через `render_view`.

### Топологические правки существующего меша

`edit_mesh_topology` изменяет native `.bmesh` с сохранением UID и материалов. Перед правкой ИИ должен получить `get_geometry` и выбирать элементы именно из локальных данных этого объекта. `set_face_material` назначает существующий слот материала выбранным треугольникам. `extrude_faces` и `inset_faces` принимают индексы треугольников одной связной плоской области с единой простой границей. Extrude двигает выбранную область вдоль её нормали и создаёт боковые грани; inset создаёт рамку и меньшую внутреннюю область. Inset допускает вогнутые контуры, если смещение сохраняет простой внутренний контур; узкий или схлопнувшийся inset отклоняется.

`bevel_edges` принимает локальные координаты концов выбранных рёбер. Операция ограничена одной выпуклой замкнутой сеткой до 4096 треугольников; смежные рёбра разрешены. Слишком большая фаска или вырожденная геометрия отклоняются. После правки нужно проверить тот же UID через `get_object` и `validate_mesh`.

`unwrap_mesh_uv` строит упакованный UV-атлас встроенным развёртывателем. Прежняя UV-развёртка сохраняется вторым набором, новый атлас становится основным и используется для текстур. `margin` задаёт нормированный отступ островов. После применения можно настроить `uv_scale` в материале и проверить UV-диагностику через `validate_mesh`.

Примитивы центрированы в локальном начале координат. Базовые box/sphere/cylinder/cone имеют габарит 1; ось cylinder/cone — Z. Torus имеет внешний диаметр 1 и толщину `2*tube` по Z до масштабирования. Curved surfaces используют сглаженные нормали; торцы и грани коробок остаются резкими. `segments` и `rings` регулируют детализацию.

Расширенные формы:

- `box` и `create_cube` принимают `face_materials` — шесть индексов палитры в порядке -Z,+Z,-Y,+X,+Y,-X. Это отдельные слоты материалов native mesh, пригодные для последующего редактирования.
- `deformed_box` принимает восемь `vertices` в порядке углов базового куба: (-,-,-),(+,-,-),(+,+,-),(-,+,-),(-,-,+),(+,-,+),(+,+,+),(-,+,+). Размер/поворот/центр применяются после деформации. Схлопнутые грани отклоняются. Произвольная новая топология задаётся общим indexed mesh. Пример `mesh_kiosk` показывает составную конструкцию из коробок с отдельными материалами и крышей из деформированного куба.

- `lathe.profile`: 2..128 пар `[radius,z]`, вращение вокруг Z. Внешняя стенка идёт снизу вверх; radius=0 замыкает торцы, обратный внутренний профиль создаёт полость. Сглаживание по окружности, изломы профиля сохраняются.
- `extrude.profile`: простой выпуклый/вогнутый XY-контур (3..128 точек), `depth` вдоль Z с центром z=0. Принимает оба направления обхода; ear clipping для крышек. Самопересечения, отверстия отдельными кольцами и повторные/коллинеарные точки не поддерживаются.
- `rounded_box.radius`: радиус 0.001..0.5 до масштабирования; `rings` 3..32 задаёт сетку грани. Неравномерный size растягивает и скругление.
- `repeat`, `step`, `rotation_step`: повторение детали с линейным сдвигом и углом каждой копии вокруг её центра; это не вращение центра по орбите. Максимум 512 частей после развёртки.
- Примеры: `mesh_robot` (составная стилизованная модель из примитивов), `mesh_kiosk`, `mesh_vase` (полая ваза), `mesh_arch` (арка из вогнутого контура), `voxel_tower` (полая башня), `mesh_bench` и `voxel_cottage`.

Альтернатива `parts`: массив `vertices` и `triangles`, где треугольник содержит `indices` из трёх индексов и `material`. Порядок вершин против часовой стрелки снаружи. В этом режиме нормали плоские; UV/vertex normals пока не принимаются.

Сервер создаёт `.bmesh`, регистрирует его через ResourceManager с checksum URL, затем публикует объект через обычные dirty/broadcast/DB механизмы. Созданная геометрия имеет native collision. Дисковая запись и расчёт геометрии выполняются вне глобального world lock.

`replace_uid` в `build_mesh`/`create_voxel_object` заменяет полную геометрию существующего доступного объекта, сохраняет UID и его transform, если новый transform не задан. Нужно передавать полный новый рецепт, а не частичный patch. Типы Generic/VoxelGroup используются для моделирования; специальные объекты редакторов требуют своих будущих адаптеров.

## Воксели

`operations` исполняются по порядку. Каждая содержит целочисленные `min`, `size`, форму `box`/`ellipsoid`/`cylinder`/`cone`/`torus`/`wedge`, режим `add`/`subtract`/`paint` и индекс материала. `axis` задаёт ось x/y/z (по умолчанию z). Cone сужается к положительному концу оси; wedge по умолчанию поднимается по +X. `shell` вычитает такую же центрированную форму со сжатым на N ячеек bounding box; это не точная постоянная толщина по нормали. Для точных стенок/открытых верхов используйте явный subtract. `tube` регулирует относительную толщину torus. `paint` меняет только существующие ячейки. Можно комбинировать с массивом `voxels`: сначала исходные ячейки, затем операции.

По умолчанию ячейка равна 0,1 м. `scale: [x,y,z]` задаёт её размер. `scale_x/y/z` сохраняются как совместимые параметры. Координаты ячеек находятся в диапазоне [-512,511]; полный span объекта — максимум 256 ячеек по каждой оси. Дубликаты ячеек объединяются.

Большие здания следует делить на разумные секции. Проёмы и интерьер вырезаются `subtract`; мелкие акценты окрашиваются `paint`. Нельзя называть сплошной заполненный объём готовым интерьером.

## Материалы и координаты

Материалы поддерживают sRGB `color: [r,g,b]` (0..1), `roughness`, `metallic`, `opacity`, `emission` и `emission_strength`. Редактирование существующих материалов передаёт полный массив слотов; пропущенные поля получают значения по умолчанию.

Мир: Z вверх, размеры в метрах. Объект: `pos: {x,y,z}`, `scale: [x,y,z]`, `axis: [x,y,z]`, `angle` в радианах. Без pos новый объект появляется в трёх метрах перед аватаром на высоте позиции аватара. Это **не автоматическое определение земли**. Для основания модели необходимо задать pos явно, учитывая локальные bounds. Позиция аватара — позиция камеры; высота поверхности инструментами пока не измеряется.

## Права на строительство

Перед созданием/расширением/перемещением модели инструкции Codex требуют `check_build_permissions` с полными мировыми bounds. Отказ содержит `BUILD_PERMISSION_DENIED` и объяснение: здесь нельзя строить; используйте свой/доступный для записи парсель, разрешённый участок песочницы или личный мир. Самостоятельно переносить модель в другое место инструкции запрещают.

Проверка является снимком, а каждый write повторно проверяет права и read-only mode. God/владелец мира сохраняют свои существующие полномочия; для остальных весь AABB должен помещаться в writable parcel и не пересекать non-writable parcel. MCP остаётся строже native placement при объединении соседних парселей: он не объединяет их границы. Логин сам по себе не означает административный доступ; слово «песочница» не обходит серверные права.

## Качество и достоверность

В контекст добавлено известное со слов владельца проекта имя создателя — Денис Шипилов; инструкции запрещают придумывать биографию или неподключённые функции. Приоритет — строительство. Инструкции встроенного Codex требуют сначала узнать возможности, выбрать место, спланировать силуэт и пропорции, затем построить крупные формы, конструктивные части и детали. Рецепты демонстрируют материалы, повторение, опоры, проёмы и разную детализацию; они не ограничивают ИИ двумя шаблонами.

После построения Codex должен вызвать `get_object` для каждого UID, сопоставить мир/bounds/материалы с намерением и сохранить рецепт для дальнейших изменений. Серверная запись объекта не доказывает, что ресурс уже загружен и красиво отрисован клиентом. Qt render callback подключён для получения снимков загруженной сцены; инструкции требуют сравнивать ракурсы и референсы. Самостоятельная визуальная оценка зависит от ответа модели и требует runtime acceptance.

Ошибки операций возвращаются как MCP `isError: true` с исходным request ID. Исправлено некорректное закрытие строки model_url старого ответа `create_cube`. Наличие UID/координат позволяет проверять результат, но само по себе не гарантирует визуальную загрузку.

## Покрытие редакторов

## Лимиты и права

- Запрос: 1 MiB; части меша: 512; входные вершины: 50 000; треугольники: 100 000.

- Создание/перемещение требует размещения всего AABB в доступном parcel, либо прав владельца мира/god user.
- Замена, копирование и удаление требуют прав редактирования исходного объекта; read-only режим соблюдается.
- Это серверные операции, они не добавляются в Qt undo stack. Для отмены изменений требуется явное обратное редактирование; для удаления — пользовательский запрос.

## Текстуры, изображения и обновление вокселей — 2026-10-07

Статус: реализовано и скомпилировано для Qt + Linux server; интерактивный сценарий этой доработки ещё не подтверждён.

### Возможности

- В ИИ → шестерёнка добавлен opt-in «Включить текстуры Poly Haven». `AI/PolyHavenEnabled` по умолчанию false; переключение не перезапускает Codex. MCP opt-in остаётся отдельным.
- Qt adapter [MCPTextureTools.h](../gui_client/MCPTextureTools.h): `search_polyhaven_textures`, `download_polyhaven_texture`, `generate_procedural_texture`, `import_image`, `draw_image`.
- Poly Haven: CC0 PBR, официальный API, собственный User-Agent, только HTTPS api.polyhaven.com/dl.polyhaven.org без redirects, 20 секунд на запрос, до 24 MiB на карту. Каталог кешируется на 15 минут. Источник указан в UI и результатах инструментов. API key не требуется: [правила API](https://polyhaven.com/our-api).
- Карты 1K/2K нормализуются до 1024 px. Передаются diffuse, OpenGL normal и packed roughness/metallic (G/B). Из измеренных dimensions API рассчитывается `uv_scale`, чтобы материал повторялся с близким к реальному физическим размером; если размеров нет — сохраняется масштаб 1×1. AO/displacement пока не применяются.
- Процедурные паттерны: wood, marble, brick, checker, noise; цвет, seed, повторение, roughness/metallic; diffuse/normal/packed PBR. Генерация/декодирование/загрузка выполняются на MCP worker, без доступа к OpenGL. Это математические текстуры, не результат нейросетевой генерации GPT Image.
- `import_image` читает реальное PNG/JPEG/WebP вложение или созданный для задачи файл. `draw_image` создаёт PNG из градиента, фигур, многоугольников и текста. `create_image` публикует двустороннюю плоскость с этой текстурой в мире с обычной проверкой прав. pos имеет формат `{x,y,z}`, начало плоскости — левый нижний угол, плоскость XZ.
- Серверный `import_texture` валидирует PNG до 2048×2048, создаёт content-addressed ресурс. JSON body ограничен 8 MiB. Импорт ресурса сам по себе не создаёт объект. Инструменты возвращают реальные URL и UID; модель должна читать результат и проверять объект.
- Материалы MCP поддерживают color_texture, metallic_roughness_texture, normal_texture, emission_texture, uv_scale и double_sided. Сохраняются существующие numeric PBR-поля. Назначение material recipes делается через build/update tools, с сохранением остальных material slots.
- Новые mesh primitives получают dominant-axis UV в локальных метрах. Это не полноценная UV-развёртка: на кривых поверхностях возможны проекционные швы. Старые MCP meshes с нулевыми UV нужно перестроить по рецепту. Для вокселей используются существующие planar UV, плотность корректируется uv_scale.
- Codex получает инструкции по этим инструментам и различию уменьшения всего объекта через scale и увеличения voxel resolution. Нейросетевая генерация возможна только при наличии настоящего imagegen tool; её доступность именно в установленном app-server не подтверждена, отдельный GPT Image API backend не добавлялся. - Отдельные agentMessage разделяются; при просмотре предыдущих сообщений streaming не принудительно прокручивает историю вниз.

Серверный `build_mesh` расширен девятью библиотечными формами: quad, capsule, icosahedron, platonic_solid, pyramid, octahedron, wedge, triangular_prism, hexagonal_prism. Cube использует box; cylinder/cone/torus/sphere и другие procedural parts были доступны ранее. Каждая часть имеет материал, размер, поворот и повторение. Серверные проверки прав и лимит 100000 треугольников сохранены.

`validate_mesh` выполняет отдельную линейную диагностику сеток до 250000 треугольников. Это не повышает лимиты редактирования и булевых операций: один булев операнд по-прежнему ограничен 4096 треугольниками.

Геометрия и normals новых форм взяты из `resources/models/*.obj`, а не придуманы в prompt. [generate_mcp_primitive_meshes.py](../scripts/generate_mcp_primitive_meshes.py) генерирует [MCPPrimitiveMeshes.h](../webserver/MCPPrimitiveMeshes.h); координаты центрированы и нормализованы по bbox. Исходная ориентация библиотеки сохраняется: например, Capsule вытянута по Y, Quad лежит в XY. Platonic_Solid — библиотечный додекаэдр. Параметры segments/rings не меняют детализацию embedded meshes. Заголовок нужен в Linux source checkout, внешние файлы моделей при запуске сервера не требуются.

Геометрические MCP-инструменты включают ограниченные Boolean-операции `boolean_mesh` для существующих объектов и упорядоченные операции внутри рецепта `build_mesh` для нового меша. Оба пути требуют закрытых согласованно ориентированных оболочек и ограничивают каждый вход 4096 треугольниками; обычные пересекающиеся детали по-прежнему остаются отдельными оболочками. `validate_mesh` показывает качество топологии и предварительно проверяет пригодность закрытой сетки для Boolean. `beveled_box` фаскует коробку; `edit_mesh_topology` добавляет ограниченные extrusion/inset планарных областей и фаски выбранных рёбер выпуклой сетки. `deform_mesh` поддерживает локальные push/inflate/smooth кисти и twist/taper по оси. Произвольные sculpt, subdivision и remeshing пока не поддерживаются.

MCP задаёт проекции UV и размещает изображение на одной грани, но полноценная интерактивная UV-развёртка, rigging и анимация, общий undo/redo редактора, постоянные параметрические рецепты и управление всеми специализированными редакторами не доступны. Rigging/анимацию планируем отдельно позже. Наличие инструментов и указаний модели не гарантирует качество произвольного результата: нужны `render_view` с нескольких углов и итерации по тому же UID.

Статически разобраны JSON схемы, проверены ключи RU-перевода AIDockWidget/CodexAppServerClient и whitespace diff. Runtime GUI/fullscreen/MCP построение не запускались; тесты не добавлялись/не запускались. Общий GUIClient/SDL путь этой доработкой не изменялся.
