# Экспорт и копирование объектов — 2026-10-12

## Реализация

Пункт меню «Экспортировать объект в glb» находится в Qt Edit menu рядом с сохранением XML. `ObjectGLBExport` снимает копию объекта под world lock и сохраняет файл через `QSaveFile` в отдельном потоке. При отсутствии исходных ресурсов запускается штатная загрузка; сообщение предлагает повторить экспорт после неё.

Экспортируются исходные native `.bmesh` и voxel objects: геометрия, UV, материалы PBR, встроенные PNG/JPEG, трансформация, поддерживаемые native skeleton/linear clips. Текстуры других поддерживаемых Qt форматов преобразуются в PNG. Запечённое освещение мира не переносится. Скрипт сохраняется только как metadata, не исполняется GLB-viewer.

Неподдерживаемые типы объектов, VRM/retargeted rigs, специальные hologram/wind/decal shaders и отдельные opacity/metallic maps вызывают явную ошибку. Ограничения: 500 000 треугольников, 1 000 000 исходных вершин, 64 MiB исходная модель, 32 MiB/32 MP текстура, 256 MiB GLB binary payload. UI/runtime roundtrip в текущей задаче не запускался.

## Права

Единая политика находится в `shared/ObjectCopyPermissions.h`:

- Superadmin (`isGodUser`, UID 0) может копировать и экспортировать объекты любого владельца в любом мире.
- Обычный пользователь — только собственные объекты, полностью находящиеся в его личном мире или внутри принадлежащего ему парселя. Writer/admin доступ к чужому парселю этого права не даёт.
- Проверяется полный world AABB относительно четырёх сторон парселя и его диапазона Z. Пересечение нескольких парселей консервативно отклоняется, даже если все они принадлежат пользователю.
- Копия также должна полностью помещаться на разрешённой пользователю территории назначения.

Qt copy/clone/paste и XML/GLB export применяют эту политику. Новый `CopyObject` передаёт исходные world/UID и позицию; сервер сам берёт данные исходника и повторно проверяет права. Clipboard geometry не считается авторитетным источником. MCP `duplicate_object` и публикация нового производного mesh применяют те же проверки.

Сетевые сообщения `CopyObject=3006`, `ObjectCopyResult=3007` согласуются через `OBJECT_COPY_SUPPORT=0x10`. Обновлённый клиент объявляет `AUTHORISED_OBJECT_COPY_SUPPORT=0x4`. Wire format прежних сообщений и protocol version не изменяются. Обычным старым клиентам без новой capability сервер запрещает `CreateObject`, чтобы старое клонирование через создание нового объекта не обходило проверку. Для строительства им нужно обновиться; просмотр и чат сохраняются.

Это ограничения штатных функций клиента и серверного copy API, а не DRM: геометрия и текстуры доставляются клиентам для отображения. Модифицированный клиент может сохранить полученные ресурсы; загрузка произвольной внешней модели не доказывает её авторство.

## Невидимые аватары

Найден путь, при котором оптимизированная модель отсутствует, исходник не закэширован у другого пользователя, а клиент подписан только на завершение загрузки оптимизированного URL. `GUIClient` теперь запрашивает исходник и подписывается на его загрузку. Завершения загрузки сверяются с текущим URL аватара, чтобы не применить устаревшую модель после смены персонажа.

Git tag `v0.0.24` использует protocol 62. Новый сервер для protocol <=62 не объявляет `OPTIMISED_MESH_SUPPORT`, направляя старый клиент к исходным моделям. Это также отключает mesh optimisation для объектов мира у этих клиентов и может увеличить объём загрузок.

Случай с двумя конкретными пользователями после обновления ещё не проверен. Отсутствующий на сервере исходник или повреждённая модель остаются отдельными причинами ошибки загрузки.
