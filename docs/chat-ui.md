# Чат и эмодзи: текущий клиент и границы

Статус: partial/WIP, проверка исходников 2026-10-04. Это описание реализации, не подтверждение live-сервера. Требования полного мессенджера остаются в [плане](CHAT_REDESIGN_PLAN_2026-06-30.md).

## Первый этап: окно эмодзи и левый чат

[ChatUI](../gui_client/ChatUI.cpp) остаётся GLUI, без Qt. Тёмное окно эмодзи использует почти непрозрачный фон, одинаковые скруглённые ячейки, центрирование глифов, подсветку активной категории, адаптивные ряды категорий и прокрутку колёсиком. На узком экране категории показаны компактными значками с подсказками. Есть поиск по английскому имени, русским категориям/ключевым словам и самому эмодзи. Закрытие — крестик, Escape или нажатие снаружи. При скрытии поиск освобождает фокус клавиатуры.

[ChatOverlayButton](../gui_client/ChatOverlayButton.h) — небольшой клиентский адаптер для фиксированной геометрии кнопок. Внешний `GLUITextButton::setPosAndDims` игнорирует размеры; внешняя библиотека не изменялась. Кнопки проверяют область отсечения и при вводе не пропускают нажатия в мир.

Общий [каталог](../gui_client/EmojiUtils.h) расширен на 50 одиночных Unicode-символов: еда/напитки и занятия/путешествия. Всего 267 уникальных эмодзи, восемь тематических категорий и «Недавние». Каталог общий с Qt-чатом. ZWJ-последовательности, флаги и модификаторы кожи по-прежнему не обещаются: текущий GL-рендерер их корректно не формирует. Используется существующий emoji-шрифт клиента, не новый скачанный пакет изображений OpenMoji.

Выбор в левом picker вставляет эмодзи в позицию курсора, не отправляет сообщение сразу. Enter или стрелка отправляют весь текст. «Недавние» сохраняются существующим SettingsStore. Левый чат хранит последние 100 сообщений текущего сеанса в памяти, показывает автора отдельно, позволяет читать историю колёсиком без принудительного перехода вниз при приходе сообщения. «К новым» возвращает к низу. Текст сообщения можно выделить и скопировать стандартным механизмом GLUI.

«Ответ» сохраняет черновик и открывает отменяемую цитату. После отправки цитата передаётся обычным текстом через текущий `ChatMessageID` и видна старым клиентам. Это **не** серверный thread/reply: нет ссылки или перехода к исходному сообщению. При отсутствии соединения черновик сохраняется. Серверное подтверждение доставки не реализовано, поэтому отправка в очередь не обозначается как «доставлено».

Кнопка свёрнутого левого чата снова использует прежнюю круглую текстуру `buttons/expand_chat_icon.png` (36 px), а не надпись «Чат». При приходе пользовательских сообщений в свёрнутый/скрытый чат или во время чтения истории появляется локальный счётчик «Новые: N» (до `99+`). Системные уведомления его не увеличивают. Нажатие открывает чат и возвращает к последним сообщениям; простой просмотр низа истории сбрасывает счётчик. Это состояние текущего сеанса, не сетевая квитанция о прочтении.

## Проверка и узкие исправления Qt-чата

- Заголовок dock «Чат» использует общую пользовательскую панель редакторов с постоянным тёмным фоном `#34343a` и светлым текстом, независимо от темы/активности окна. Панель сохраняет кнопки закрытия и отделения от главного окна.
- Добавлен поиск без учёта регистра по тексту/автору в уже загруженных сообщениях выбранного общего или личного диалога. Ctrl+F переводит фокус в поиск, Enter/Shift+Enter и стрелки переходят по совпадениям, счётчик показывает текущий результат, Esc/крестик очищают поиск и возвращают фокус в черновик. Выбранное сообщение выделяется рамкой; контекст диалога остаётся виден. Это локальный поиск, не запрос серверного архива.
- Приход сообщения в Qt больше не переносит читателя вниз, если он прокрутил историю вверх или использует поиск. Автопрокрутка сохраняется для просмотра последних сообщений.
- Текстовая цитата больше не заменяет существующий черновик; проверяется максимальная длина.
- При выключенной сетевой отправке личных сообщений или отсутствии адресата черновик остаётся; локальная запись не изображает отправленное сообщение.
- Проверка адресата и настройки личных сообщений выполняется до загрузки вложений. При отсутствии соединения отправка текста и выбор вложения прерываются без стирания черновика.
- Лайки раньше записывали локальное свойство виджета и рисовали «1». Эти неподключённые действия отключены с объяснением; сетевых лайков пока нет.
- Жалоба на сообщение не изображает отправку в очередь модерации. «Удалить у всех» недоступно без серверной реализации; локальное удаление и копирование сохранены.

## Что ещё необходимо для полноценного чата

| Приоритет | Необходимая реализация | Текущая граница |
| --- | --- | --- |
| P1 | Строгая адресация личных сообщений по UID | Исправлено в исходниках `Server::enqueuePrivateChatPacketForWorld`: если UID указан, совпадение другого имени не расширяет получателей. Fallback по имени только без UID. Нужны проверка несколькими клиентами и отдельный Linux deploy; production не менялся. |
| P1 | Серверные ID сообщений и проверка возможностей клиента/сервера | `ChatMessageID` — тип пакета, не ID конкретного сообщения. Входящая модель содержит автора/текст/UID, но не ID, время или revision. |
| P1 | Настоящие ответы и реакции | Parent ID, проверка доступа к сообщению, идемпотентный toggle, список/количество реакций, broadcast обоим UI, сохранение в истории. Не подменять обычными локальными счётчиками. |
| P2 | Доставка, ошибки, повтор, восстановление истории | Нужны ACK и client nonce, исключение дублей, страницы истории, unread и сохранение позиции чтения. Локальная история Qt не равна общей серверной истории. |
| P2 | Поиск сообщений и организация диалогов | Qt поддерживает поиск по тексту/автору в загруженном диалоге и переход к результату. Ещё нужны поиск по дате/серверному архиву, закрепления и редактирование с revisions. Поиск в GLUI picker ищет только эмодзи, не историю чата. |
| P2 | Права, жалобы, блокировки, редактирование и удаление | Серверная проверка авторства/ролей. Бейдж, вычисленный из имени, не должен давать права. Ряд действий игроков пока лишь сообщает «позже». |
| P2 | Группы и личные диалоги | Сейчас группы локальны; нужны серверное членство, приглашения, доступ к истории и сообщениям. |
| P3 | Свои эмодзи/стикеры | Нужны стабильный ID, ограничение размера/разрешения, безопасное декодирование PNG/WebP, ресурсный URL, права удаления, кеш и отображение на обоих UI. Существующая отправка вложений — транспортная основа, но не готовая система custom emoji. |

Изменять серверный протокол и разворачивать сервер следует отдельным согласованным этапом с обратной совместимостью. В этой итерации исправлен только UID-фильтр в исходниках сервера, без изменения протокола. Работающий сервер, production, пользовательские истории и настройки напрямую не изменялись.

## Проверки

[Изолированные тесты](../scripts/chat_ui_tests/CMakeLists.txt): каталог/поиск RU и EN, уникальность, фильтрация недавних, отказ для неправильного UTF-8; геометрия 320–1920 × 280–1080, отсутствие пустого окна на промежуточных позициях прокрутки; локальный счётчик непрочитанного, насыщение и сброс. Не запускают клиент, не читают историю и не подключаются к серверу.

Локальные Qt `gui_client` и Windows `server` собраны в RelWithDebInfo на первом этапе. Три CPU-теста прошли после восстановления иконки и добавления счётчика. Это compile/link и логические проверки, не запуск клиента/сервера и не Linux production-проверка.

После продолжения чата Qt-клиент повторно собран 2026-10-04: canonical `RelWithDebInfo/gui_client.exe` обновлён (83 032 576 bytes), build manifest: `success=true`, `runtime_ready=true`. Запуск клиента не выполнялся; визуальная проверка заголовка, поиска и индикатора новых сообщений остаётся ручной.

Изменённые common-файлы `ChatUI.cpp` и `GUIClient.cpp` проверяются отдельной компиляцией Emscripten. Полная Web-сборка заблокирована отсутствующим preload `data`; Web-ready не подтверждён, preload/cache-hash/deploy не выполнялись.

Ручной acceptance ещё нужен: узкий viewport и открытый Qt dock, 100+ сообщений, приход новых при прокрутке, выделение/копирование, сохранность черновика при ответе/отключении, вставка эмодзи в середину текста, Escape после поиска, смена мира, отсутствие кликов в мир через окно. Клиент при разработке не запускался по прежнему указанию владельца.
